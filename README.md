# به سوی رویا — مسابقهٔ مهارتی «نقطهٔ توپ»

پلتفرم کامل یک مسابقهٔ مهارتی به سبک Spot the Ball: وب‌سایت عمومی، بازی، سبد خرید و پرداخت، کنسول داوری و پنل مدیریت.

بک‌اند با **Go 1.22** و PostgreSQL، فرانت‌اند با **Next.js 14** (App Router) و رابط فارسی راست‌به‌چپ. همهٔ کد، متن و طراحی از صفر نوشته شده است؛ هیچ دارایی یا محتوایی از سایت مرجع کپی نشده.

---

## چرا «نقطهٔ توپ» و نه کمترین پیشنهاد

در بیشتر کشورهای اروپایی، مسابقهٔ «کمترین پیشنهاد یکتا» عملاً قرعه‌کشی محسوب می‌شود و مجوز جداگانه می‌خواهد. مکانیک این پروژه مبتنی بر **مهارت** است: بازیکن حدس می‌زند توپ حذف‌شده از عکس کجا بوده و یک هیئت داوران مستقل نقطهٔ درست را تعیین می‌کند.

دو سپر حقوقی همیشه فعال‌اند و نباید حذف شوند:

۱. **مسیر ورود رایگان** (`/free-entry`) — شرکت بدون خرید همیشه ممکن است.
۲. **لایهٔ واقعی مهارت** — نقطه را داوران انسانی تعیین می‌کنند، نه یک عدد تصادفی.

## معماری ضدتقلب

نگرانی اصلی این است که یک ادمین داخلی مختصات درست را بفروشد. طراحی چند لایه دارد:

- **تعهد و افشا (commit–reveal):** داور پیش از بسته شدن مسابقه فقط `sha256("%.6f|%.6f|nonce")` را ثبت می‌کند. خود نقطه بعد از بسته شدن افشا می‌شود و سرور تطابق را بررسی می‌کند. حتی مدیر کل هم پیش از بسته شدن نقطه را در پایگاه داده ندارد.
- **مختصات مهرشده:** تا وقتی مسابقه `open` یا `draft` است، `ListEntries` مختصات هیچ پیشنهادی را برنمی‌گرداند — برای هیچ نقشی.
- **زنجیرهٔ هش:** هر پیشنهاد `sha256(prev|id|user|comp|x|y|unixnano)` را ذخیره می‌کند. دکمهٔ «بررسی زنجیرهٔ هش» در پنل، دستکاری یا حذف رکورد را آشکار می‌کند. همین بررسی داخل `Settle` هم به‌اجبار اجرا می‌شود، پس تسویه به یادآوری ادمین وابسته نیست.
- **ناظر مستقل (`auditor`):** شکستن زنجیره به‌جای یک پیام روی صفحهٔ ادمین، در جدول `integrity_incidents` ثبت می‌شود. این جدول با تریگر پایگاه‌داده فقط‌افزودنی است: حذف ممکن نیست، فاکت‌ها تغییرناپذیرند و حادثهٔ بسته‌شده بازگشایی نمی‌شود. تا وقتی حادثهٔ رسیدگی‌نشده‌ای وجود دارد، تسویهٔ آن مسابقه قفل است و تنها حساب `auditor` می‌تواند آن را باز کند — `superadmin` عمداً مستثنا **نیست** (`RequireExactRole`).
- **پرچم insider:** کارکنان و بستگانشان علامت می‌خورند و از برنده شدن کنار گذاشته می‌شوند.
- **گزارش ممیزی فقط‌افزودنی:** هر اقدام مدیریتی با هویت انجام‌دهنده و IP ثبت می‌شود.

جزئیات بیشتر در [ARCHITECTURE.md](ARCHITECTURE.md).

## دیدن طراحی بدون نصب

فایل [`preview.html`](preview.html) یک پیش‌نمایش ایستا و تک‌فایلی است: با دوبار کلیک در مرورگر باز می‌شود و صفحهٔ اصلی، صفحهٔ بازی و سه صفحهٔ پنل مدیریت را نشان می‌دهد. به API وصل نیست و فقط برای تأیید طراحی است — برنامهٔ واقعی همان کد Next.js داخل `web/` است.

## اجرا با Docker

```bash
cp .env.example .env
docker compose up --build -d
docker compose run --rm seed        # دادهٔ نمونه
```

سپس: وب‌سایت روی <http://localhost:3000> و API روی <http://localhost:8080>.

## اجرای دستی

پیش‌نیاز: Go 1.22+، Node 20+، PostgreSQL 14+.

```bash
# پایگاه داده
createdb dreamdrive

# API — مهاجرت‌ها هنگام بالا آمدن خودکار اجرا می‌شوند
cd api
go mod download
go run ./cmd/server

# دادهٔ نمونه، در ترمینال دیگر
go run ./cmd/seed

# فرانت‌اند
cd ../web
npm install
npm run dev
```

```
api/
  cmd/server        نقطهٔ ورود HTTP
  cmd/seed          دادهٔ نمونه
  migrations/       SQL، با go:embed داخل باینری
  internal/auth     JWT، bcrypt، نقش‌ها
  internal/store    لایهٔ داده: catalog, commerce, judging, integrity, users, cms
  internal/api      مسیرها؛ admin.go، public.go، auditor.go
web/
  app/              صفحه‌های عمومی، /play، /admin، /judge، /audit
  components/       SpotBoard، آیکون‌ها، Markdown، اجزای پنل
  lib/api.ts        کلاینت تایپ‌دار API
```

فرانت‌اند هیچ وابستگی زمان‌اجرایی بیرون از Next/React/Tailwind ندارد — آیکون‌ها، رندر مارک‌داون و نمودار همه دستی نوشته شده‌اند.

## نقش‌ها

`user` · `support` · `content_admin` · `finance_admin` · `judge` · `auditor` · `superadmin`

`superadmin` به همه چیز دسترسی دارد — به‌جز `/audit` و مسیرهای `/api/auditor`. این یک استثنای عمدی است: ناظری که زیرمجموعهٔ مدیریت باشد مستقل نیست و می‌توانست حادثهٔ خودش را ببندد. بقیه فقط به بخش‌های خودشان؛ گیت هم سمت سرور روی هر مسیر و هم در `app/admin/layout.tsx` اعمال می‌شود.

## تصویرها و انبارهٔ فایل

تصویرهای پنل (تصویر شاخص جایزه، تختهٔ بازی، بنر صفحهٔ اصلی) مستقیم از همان فرم‌ها آپلود می‌شوند: دکمهٔ «انتخاب فایل» یا کشیدن و رها کردن فایل روی کادر. فایل به `POST /api/admin/uploads` می‌رود و نشانی نهایی‌اش در فیلد ذخیره می‌شود. چسباندن نشانی بیرونی هم همچنان کار می‌کند.

دو راننده وجود دارد و با یک متغیر عوض می‌شوند:

| `STORAGE_DRIVER` | فایل کجا می‌رود | مناسب چه زمانی |
| --- | --- | --- |
| `local` (پیش‌فرض) | پوشهٔ `UPLOAD_DIR` روی همان سرور، سرو شده روی `/uploads/` | توسعه یا یک سرور تکی |
| `s3` | هر سرویس سازگار با S3 — MinIO، آروان، لیارا، AWS | چند نمونهٔ API، CDN، یا وقتی دیسک سرور نباید حالت داشته باشد |

با `docker compose up` یک MinIO هم بالا می‌آید و `api` به‌صورت پیش‌فرض روی همان تنظیم شده؛ کنسولش روی <http://localhost:9001> با `minioadmin / minioadmin` است. برای رفتن روی سرویس ابری فقط چهار متغیر `S3_ENDPOINT`، `S3_BUCKET`، `S3_ACCESS_KEY` و `S3_SECRET_KEY` را عوض کن. اگر `STORAGE_DRIVER=s3` باشد و یکی از این چهارتا خالی بماند، سرور همان لحظهٔ بالا آمدن با خطا متوقف می‌شود — عمدی است، تا خرابی وسط کار ادمین معلوم نشود.

نکتهٔ مهم: `S3_ENDPOINT` نشانی‌ای است که *API* برای نوشتن استفاده می‌کند و `S3_PUBLIC_BASE` نشانی‌ای که *مرورگر کاربر* برای خواندن. در داکر این دو فرق دارند (`http://minio:9000` در برابر `http://localhost:9000/dreamdrive`) چون مرورگر نام سرویس داکر را نمی‌شناسد. سطل باید اجازهٔ خواندن عمومی داشته باشد؛ سرویس `minio-init` این کار را خودکار انجام می‌دهد.

محدودیت‌ها: حداکثر ۸ مگابایت، فقط JPG/PNG/WebP/AVIF/GIF. نوع فایل از روی محتوای واقعی تشخیص داده می‌شود نه پسوند یا هدر، و SVG عمداً پذیرفته نمی‌شود چون می‌تواند جاوااسکریپت اجرا کند و از دامنهٔ خودمان سرو می‌شود.

## پیش از راه‌اندازی عملیاتی

- [ ] `JWT_SECRET` را با `openssl rand -hex 32` بساز و `APP_ENV=production` بگذار (سرور با کلید پیش‌فرض بالا نمی‌آید).
- [ ] درگاه پرداخت واقعی را وصل کن؛ فعلاً پرداخت شبیه‌سازی‌شده است. `PAYMENT_WEBHOOK_SECRET` را بگذار — بدون آن `POST /api/payments/webhook` غیرفعال است، و با آن هر درخواست باید هدر `X-Signature` با `HMAC-SHA256(body, secret)` داشته باشد.
- [ ] TLS و یک reverse proxy جلوی هر دو سرویس.
- [ ] KYC واقعی پیش از پرداخت جایزه.
- [ ] متن قوانین و شرایط را با وکیل کشور ثبت شرکت نهایی کن. صفحه‌های حقوقی موجود نمونه‌اند، نه مشاورهٔ حقوقی.
- [ ] پشتیبان‌گیری منظم و آزمون بازیابی پایگاه داده.
