# به سوی رویا — مسابقهٔ مهارتی «نقطهٔ توپ»

پلتفرم کامل یک مسابقهٔ مهارتی به سبک Spot the Ball: وب‌سایت عمومی، بازی، سبد خرید و پرداخت، کنسول داوری و پنل مدیریت.

بک‌اند با **Go 1.22** و PostgreSQL، فرانت‌اند با **Next.js 14** (App Router) و رابط فارسی راست‌به‌چپ. همهٔ کد، متن و طراحی از صفر نوشته شده است؛ هیچ دارایی یا محتوایی از سایت مرجع کپی نشده.

---

## چرا «نقطهٔ توپ» و نه کمترین پیشنهاد

در بیشتر کشورهای اروپایی، مسابقهٔ «کمترین پیشنهاد یکتا» عملاً قرعه‌کشی محسوب می‌شود و مجوز جداگانه می‌خواهد. مکانیک این پروژه مبتنی بر **مهارت** است: بازیکن حدس می‌زند توپ حذف‌شده از عکس کجا بوده و یک هیئت داوران مستقل نقطهٔ درست را تعیین می‌کند.

دو سپر حقوقی همیشه فعال‌اند و نباید حذف شوند:

۱. **مسیر ورود رایگان** (`/free-entry`) — شرکت بدون خرید همیشه ممکن است.
۲. **لایهٔ واقعی مهارت** — نقطه را داوران انسانی تعیین می‌کنند، نه یک عدد تصادفی.

## معماری ضدتقلب

نگرانی اصلی این است که یک ادمین داخلی مختصات درست را بفروشد. طراحی چند لایه دارد:

- **تعهد و افشا (commit–reveal):** داور پیش از بسته شدن مسابقه فقط `sha256("%.6f|%.6f|nonce")` را ثبت می‌کند. خود نقطه بعد از بسته شدن افشا می‌شود و سرور تطابق را بررسی می‌کند. حتی مدیر کل هم پیش از بسته شدن نقطه را در پایگاه داده ندارد.
- **مختصات مهرشده:** تا وقتی مسابقه `open` یا `draft` است، `ListEntries` مختصات هیچ پیشنهادی را برنمی‌گرداند — برای هیچ نقشی.
- **زنجیرهٔ هش:** هر پیشنهاد `sha256(prev|id|user|comp|x|y|unixnano)` را ذخیره می‌کند. دکمهٔ «بررسی زنجیرهٔ هش» در پنل، دستکاری یا حذف رکورد را آشکار می‌کند.
- **پرچم insider:** کارکنان و بستگانشان علامت می‌خورند و از برنده شدن کنار گذاشته می‌شوند.
- **گزارش ممیزی فقط‌افزودنی:** هر اقدام مدیریتی با هویت انجام‌دهنده و IP ثبت می‌شود.

جزئیات بیشتر در [ARCHITECTURE.md](ARCHITECTURE.md).

## دیدن طراحی بدون نصب

فایل [`preview.html`](preview.html) یک پیش‌نمایش ایستا و تک‌فایلی است: با دوبار کلیک در مرورگر باز می‌شود و صفحهٔ اصلی، صفحهٔ بازی و سه صفحهٔ پنل مدیریت را نشان می‌دهد. به API وصل نیست و فقط برای تأیید طراحی است — برنامهٔ واقعی همان کد Next.js داخل `web/` است.

## اجرا با Docker

```bash
cp .env.example .env
docker compose up --build -d
docker compose run --rm seed        # دادهٔ نمونه
```

سپس: وب‌سایت روی <http://localhost:3000> و API روی <http://localhost:8080>.

## اجرای دستی

پیش‌نیاز: Go 1.22+، Node 20+، PostgreSQL 14+.

```bash
# پایگاه داده
createdb dreamdrive

# API — مهاجرت‌ها هنگام بالا آمدن خودکار اجرا می‌شوند
cd api
go mod download
go run ./cmd/server

# دادهٔ نمونه، در ترمینال دیگر
go run ./cmd/seed

# فرانت‌اند
cd ../web
npm install
npm run dev
```

## چیدمان پروژه

```
api/
  cmd/server        نقطهٔ ورود HTTP
  cmd/seed          دادهٔ نمونه
  migrations/       SQL، با go:embed داخل باینری
  internal/auth     JWT، bcrypt، نقش‌ها
  internal/store    لایهٔ داده: catalog, commerce, judging, users, cms
  internal/api      مسیرها؛ admin.go و public.go
web/
  app/              صفحه‌های عمومی، /play، /admin، /judge
  components/       SpotBoard، آیکون‌ها، Markdown، اجزای پنل
  lib/api.ts        کلاینت تایپ‌دار API
```

فرانت‌اند هیچ وابستگی زمان‌اجرایی بیرون از Next/React/Tailwind ندارد — آیکون‌ها، رندر مارک‌داون و نمودار همه دستی نوشته شده‌اند.

## نقش‌ها

## پیش از راه‌اندازی عملیاتی

- [ ] `JWT_SECRET` را با `openssl rand -hex 32` بساز و `APP_ENV=production` بگذار (سرور با کلید پیش‌فرض بالا نمی‌آید).
- [ ] درگاه پرداخت واقعی را وصل کن؛ فعلاً پرداخت شبیه‌سازی‌شده است. `PAYMENT_WEBHOOK_SECRET` را بگذار — بدون آن `POST /api/payments/webhook` غیرفعال است، و با آن هر درخواست باید هدر `X-Signature` با `HMAC-SHA256(body, secret)` داشته باشد.
- [ ] TLS و یک reverse proxy جلوی هر دو سرویس.
- [ ] KYC واقعی پیش از پرداخت جایزه.
- [ ] متن قوانین و شرایط را با وکیل کشور ثبت شرکت نهایی کن. صفحه‌های حقوقی موجود نمونه‌اند، نه مشاورهٔ حقوقی.
- [ ] پشتیبان‌گیری منظم و آزمون بازیابی پایگاه داده.
